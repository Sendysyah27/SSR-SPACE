# P2-R3: Dompet paling sering dipakai

## Problem

Dropdown dompet selalu urut abjad. Pengguna dengan 5 sampai 8 dompet
mengulang scroll ke dompet yang sama setiap kali catat, padahal pola
pakainya jelas: 1 atau 2 dompet dipakai hampir tiap hari.

## Pola Ollo

Ollo 1.6.0 mengurutkan wallet picker dengan default Most used.
Referensi alur saja, tanpa salin kode.

## Adaptasi SSR

Modul murni `lib/services/wallet_usage.dart`: `recordUse(counts, id)`
dengan cap 50 entri dan batas hitung, plus `sortIdsByUse()` (hitung DESC,
nama ASC sebagai seri). Hitung disimpan di prefs `wallet_use_count`
sebagai JSON. Increment hanya saat simpan manual lewat `TxInputSheet`
dan koreksi instan berhasil, tidak dari auto-track agar mesin tidak
menaikkan skornya sendiri. Dropdown form memakai urutan ini, tanpa badge
atau label baru agar nada tetap tenang.

## Data dan prefs

Tanpa migration. Satu prefs baru `wallet_use_count` (JSON map id ke int,
fail-safe ke map kosong bila korup). Tidak ada data server baru.

## Edge cases

Prefs korup atau kosong: urut abjad seperti sekarang. Dompet dihapus:
entrinya diabaikan saat sort (tak ada prune; cap 50 membatasi bloat).
Cap 50: id terlama dengan hitung terkecil dibuang dulu. Ganti workspace: hitung bersifat lokal
per HP, dipakai lintas workspace apa adanya dan didokumentasikan.

## Daftar test

Satu pakai menaikkan hitung satu. Cap membuang entri terkecil saat penuh.
Sort menempatkan hitung besar dulu, seri ikut abjad. JSON korup kembali
ke map kosong. Auto-track tidak memanggil recordUse (assert via review
jalur, bukan hitung tersembunyi).

## Dampak Supabase dan RLS

Tanpa migration. Tidak ada baca atau tulis server baru. Semua state di
prefs lokal.
